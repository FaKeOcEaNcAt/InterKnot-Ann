# 架构

`scripts/official.py` 默认使用 HoYoverse 中文官网资讯页所用的公开列表接口 `getContentList`，查询应用 `3e9196a4b9274bd7`、新闻频道 `288` 和语言 `zh-cn`。列表携带正文、来源 ID 和 CMS 发布时间。中文频道的无时区字段 `dtStartTime` 按北京时间解释。页面正文仅在采集时用标准库提取纯文本用于分类和时间摘要，原始 HTML 不输出。保留官网与 Bilibili 的独立 ID、详情及原文链接。首页同日同标题的跨源公告优先显示官网条目，已置顶或配置外链配图的 Bilibili 条目保留在列表。

`scripts/bilibili.py` 通过账号图文列表发现记录，再通过详情校验动态 ID、账号 UID 1636034895 和 Unix 发布时间。传输使用固定主机、HTTPS、有限分页和有间隔的请求。详情中的活动标题和正文结构共同参与分类。转发、普通视频和单纯的社交抽奖会过滤，附带社交推广的正式游戏公告仍可保留游戏部分。无法分类的官方图文进入其他官方资讯。分类规则仍需随真实样本校正。

`scripts/sync.py` 以来源 ID 合并，比较经过规范化的标题、正文及可识别的图像引用摘要。上游只有摘要时，摘要之外的编辑未必能检测。相同标题可以对应多条官方发布，保留不同来源 ID 的时间线。上游删除、暂时漏报、超出扫描窗口等情况保留历史条目。首屏经验证的置顶状态会更新。首次匹配人工条目时用实际秒级发布时间校正分钟精度，并保留已核对的导读。后续变更时间表示本站发现时间。一次运行先验证全部待写入数据，再原子替换一个 JSON 文件。

`scripts/build.py` 生成平面目录结构，使站点可发布在项目子路径或自定义域名。列表每页 12 条，详情用时间顺序连接。模板变量和数据字段通过 HTML 转义写入，正文只支持段落和小标题。内容默认是导读及来源入口。搜索只在提交时按块请求同源索引，每块 100 条，最多插入 100 个搜索结果。静态图片分正文和缩略图，现代浏览器延迟加载，IE 可按普通图片加载。

Actions 将只读测试和构建、归档提交以及 Pages 发布分成三个 Job。只向构建和写入任务之间传递已验证的固定归档文件，写入时从同一源提交开始，普通 Git push 会拒绝并发的非快进修改。生成站点保存在 Pages artifact，源归档持久化至默认分支。部署失败后可用 `build_only` 重发已写入的归档。按小时调度按页数和截止日扫描，页预算触顶时打印覆盖可能不全。
