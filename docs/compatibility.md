# 浏览器兼容性

页面以标准文档模式、预渲染 HTML、ES5 和行内块百分比布局实现。它使用系统字体、基础媒体查询和传统 DOM API。IE 使用普通图片加载及同源 XMLHttpRequest 搜索。无脚本时可浏览首页、分类、历史分页和详情。样式同时包含 viewport meta 和 `@-ms-viewport`。

全屏入口在 Windows Phone 或检测到 Fullscreen API 的浏览器上出现。用户点击后尝试浏览器提供的标准或 MS 前缀 API，并提供退出入口。浏览器控制的底部菜单和系统导航区域取决于系统与浏览器能力。若 API 缺失或被拒绝，页面提示后保留阅读功能。Microsoft 记载 IE11 Mobile 可将站点固定到开始屏幕，具体工具栏行为需在设备确认。 [Windows Phone IE11 功能说明](https://blogs.windows.com/windowsexperience/2014/05/07/a-closer-look-at-internet-explorer-11-for-windows-phone/)

## Lumia 920 验收

1. 确认系统为 Windows Phone 8.1，时间、根证书与系统补丁可用。使用移动版 Internet Explorer 打开已部署 HTTPS 地址。记录是否出现协议、证书或连接错误。
2. 依次在竖屏、横屏打开首页、分类、详情。记录实际 CSS 视口、系统菜单所占空间和字体缩放。物理像素尺寸不能代替 CSS 视口。
3. 验证 44 CSS px 级触控目标、长中文标题、图片、返回链接、关键词搜索及上一条和下一条链接。
4. 点击「全屏」，分别记录网页进入全屏、底部菜单消失和退出恢复三种结果。检查从开始屏幕固定站点进入时的表现。
5. 禁用脚本或测试脚本请求失败，验证主要页面与分页。记录外部原文能否由目标设备直接打开。

用户在 Lumia 920 真机上确认各页面能打开，且按钮能进入全屏，同时报告全屏后无法上下拖动和屏幕底部出现白边。全屏样式已针对 Windows Phone 的 MS 全屏状态明确使用正文滚动容器，等待真机复测。底部白边成因尚未确认。ES5 解析与模拟 MS 全屏检查不覆盖真机触控滚动。

## HTTPS

发布后从目标设备测试实际 Pages 或自定义域名的 TLS 握手、证书链、信任根、套件与 SNI。在服务器侧可另做 TLS 1.2 和证书链检测，并记录实测域名与日期。若 Pages 握手与该设备不兼容，页面代码无法调整握手。可将同一份静态构建发布在独立 HTTPS 入口，选用目标设备信任的公共 CA 证书链，在服务器配置经验证的安全 TLS 1.2/1.3 套件，并为现代客户端保留 TLS 1.3。替代入口也要经过真机验证。
