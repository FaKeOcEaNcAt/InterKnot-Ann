# 安全设计与剩余风险

- 采集把来源数据作为 JSON 解析，拒绝重复键、非有限常量、意外格式、错误作者、非法 ID、异常时区、超长字段和危险控制字符。来源 URL 由验证过的 ID 拼接。原文只通过链接访问。
- 采集的 HTTPS 主机和端点固定，外部重定向会失败。响应有 MIME、编码、读取大小和超时约束，访问受限时终止整轮。日志只记录受控状态和异常类型。正文中的远程图片引用只用于检测内容变更，采集器不下载图片。
- 构建使用显式资产清单和经过验证的本地图片。图片有文件名、体积、格式签名和尺寸约束。格式头检查属于最低限度校验，发布前仍需从可信来源取得许可、重新编码并审阅实际图像。
- 审核后手动配置的 Bilibili CDN 图片由浏览器直连。构建与输出检查均验证 URL，现代浏览器通过 CSP 限定 CDN 域名并请求省略来源页地址。启用该配置会将访客 IP 暴露给图片 CDN。IE11 可能忽略现代策略，因此域名和路径的服务端验证仍是主要约束。
- 静态模板对外来文本做 HTML 转义，搜索用 `textContent` 创建节点。无外部脚本、iframe、帐号、客户端 Bilibili API 调用或跟踪。Pages 产物核验拒绝危险链接、行内处理器和未知文件。
- 现代浏览器适用页面内的 CSP。Pages 原生托管的 HTTP 响应头由平台控制。需要 `frame-ancestors`、`X-Content-Type-Options: nosniff` 或 HTTP 形式的 `Referrer-Policy` 时，可将同一静态构建发布在可配置响应头的托管入口。IE11 的主要保障来自转义、URL 验证及无第三方执行路径。
- PR 运行只读检查，写任务和部署任务要求受信任的默认分支运行成功。Actions 固定到从官方仓库核对的发布提交。工作流不需要额外 Secrets，Python 构建无第三方运行时依赖。
- Windows Phone 和 IE11 已停止维护，浏览器自身漏洞与站点隔离措施是两类风险。第三方源站的政策、响应形状、历史缺失和时间字段变化可能使采集暂停。正文许可和原文的可访问性分别需要维护者核对。
